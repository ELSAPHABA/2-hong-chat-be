분산형 실시간 채팅 시스템 기능 명세서 (K8s & State Sharing 중심)
1. 프로젝트 개요
* 주제: FastAPI와 Redis Pub/Sub 기반의 분산 확장형 실시간 1:1 채팅 서버 구현.
* 핵심 목표: Kubernetes 환경에서 다수의 Pod가 가로로 확장(Scale-out)되더라도 유저 간 상태 정보를 완벽히 공유하고 실시간 메시지를 중계하는 시스템 구축.
2. 기술 스택
* Backend: FastAPI (Python 3.10+).
* Real-time: WebSockets.
* Message Broker: Redis (Pub/Sub 기능 활용).
* Database: MongoDB.
* Concurrency: redis-py의 비동기 Pub/Sub 또는 broadcaster 라이브러리 활용.

3. 시스템 아키텍처: Redis를 이용한 상태 공유 (State Sharing)
다중 서버 환경에서는 유저 A와 B가 서로 다른 Pod에 접속할 수 있으므로, Redis를 **전역 메시지 버스(Message Bus)**로 활용합니다.
* 메시지 전파 흐름:
1. 발행 (Publish): 특정 Pod가 유저로부터 메시지를 받으면, 해당 룸의 Redis 채널(room_{room_id})에 메시지를 발행합니다.
2. 공유 (State Sharing): 클러스터 내의 모든 Pod는 모든 활성화된 채팅방 채널을 구독하고 있습니다.
3. 전달 (Delivery): Redis로부터 메시지를 수신한 각 Pod는 "현재 나에게 연결된 유저 중 이 방의 멤버가 있는가?"를 확인한 후, 존재한다면 해당 유저의 웹소켓 세션으로 메시지를 전송합니다.

4. 세부 기능 요구사항
① WebSocket 연결 관리
* 엔드포인트: /ws/{room_id}/{user_id}를 통해 연결을 수립합니다.
* 구독 로직: 연결 시 해당 Pod는 Redis의 특정 채널(room_{room_id})에 대한 구독을 시작합니다.
* 연결 유지: K8s의 Liveness/Readiness Probe에 대응할 수 있도록 비정상 종료 시 세션을 정리하는 로직을 포함합니다.
② 메시지 흐름 및 동기화
* 실시간 중계: 사용자가 메시지를 보내면 서버는 즉시 Redis 채널에 발행하여 다른 모든 서버 인스턴스가 이를 수신하게 합니다.
* 동시성 처리: 비동기 루프를 통해 Redis 메시지 수신과 클라이언트 메시지 발신이 독립적으로 작동하도록 구현합니다.
③ 데이터 영속성 (Storage)
* 비동기 저장: 메시지 중계와 별도로, 모든 내역은 MongoDB에 비동기로 저장됩니다.
* 저장 항목: room_id, sender_id, message_text, timestamp.
* 내역 조회: 채팅방 진입 시, 해당 방의 과거 대화 내역 최근 50개를 불러오는 REST API를 제공합니다.

5. 
폴더 구조 및 출력 요청사항 
1. 폴더 구조:
o app/main.py: FastAPI 초기화 및 웹소켓 핸들러.
o app/core/redis_client.py: Redis 연결 및 비동기 Pub/Sub 로직.
o app/models/schemas.py: MongoDB 및 Pydantic 데이터 모델.
o app/services/chat_service.py: 메시지 발행 및 DB 저장 비즈니스 로직.
2. K8s 배포 고려: 컨테이너화를 위한 Dockerfile 및 다중 인스턴스 설정을 위한 deployment.yaml 예시 포함.

6. 확장성(Scalability) 운영 전략
* Stateless 서비스: 백엔드 파드는 어떤 상태 정보(예: 특정 유저의 메시지 큐)도 로컬 메모리에 영구 저장하지 않으며, 모든 상태는 Redis와 MongoDB에 위임합니다.
* Scale-out: 트래픽 증가 시 K8s의 HPA(Horizontal Pod Autoscaler)를 통해 Pod 개수를 늘려도 Redis Pub/Sub 덕분에 메시지 유실 없이 즉시 확장이 가능합니다.
